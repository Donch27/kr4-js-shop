# IceForce — КР №4 (`kr4-js-shop`)

**Дисциплина:** «Фронтенд и бэкенд разработка».  
**Тема:** «JavaScript: интерактивность, DOM, события, формы и валидация».  
**Автор:** Дончу Артём, **группа ЭФБО-03-25** (сохранены данные из исходного проекта).  
**Основа:** контрольная работа №3 `kr3-responsive-shop`, адаптивный HTML/CSS-магазин хоккейной экипировки IceForce.

Это **отдельная версия** интернет-магазина на чистом JavaScript, без React, Vue, Bootstrap, сторонних библиотек и бэкенда. Внешний вид, адаптивные стили, фотографии и основные страницы КР №3 сохранены.

> **Важно:** оформление заказа — учебная имитация. Серверной отправки данных, онлайн-оплаты и настоящего магазина нет. Персональные данные, введённые в формы, никуда не передаются; в `localStorage` сохраняются только идентификаторы/количество товаров, избранное и тема.

## Как открыть проект в VS Code

1. Распакуйте `kr4-js-shop.zip`.
2. Откройте **VS Code → File → Open Folder → `kr4-js-shop`**.
3. Откройте `index.html` через расширение **Live Server** (*Go Live*) или запустите локальный сервер из папки проекта: `python -m http.server 8000`.
4. В браузере откройте `http://localhost:8000/index.html`. К каталогу можно перейти по меню или напрямую по `catalog.html`.
5. Для проверки JS откройте **F12 → Console**; в обычном режиме не должно быть ошибок. Сервер базы данных и `npm install` не нужны.

Можно открыть `index.html` двойным кликом, но локальный сервер через Live Server удобнее для тестирования, ссылок и `localStorage`.

## Базовые требования КР №4

| Требование | Реализация |
|---|---|
| Массив 8–12 товаров | `js/data.js`: 12 объектов `products` с едиными полями `id`, `title`, `category`, `price`, `isAvailable` и дополнительными полями (фото, размеры, описание и т. п.). `id` уникальны, цена — число. |
| Создание карточек в JS | `createProductCard()` в `catalog.js`; карточки не написаны в HTML каталога. |
| DOM | Используются `querySelector`, `createElement`, `textContent`, `classList.add/toggle`, `append`, `replaceChildren`. |
| Безопасный вывод | Тексты товаров, результаты формы, пользовательские данные и корзина выводятся через `textContent`; `innerHTML` для них не используется. |
| Поиск | В `catalog.html`: поле «Поиск по названию». Событие `input`, поиск без учёта регистра и по части названия. |
| Категории | Чекбоксы «Одежда», «Защита», «Инвентарь»; можно выбрать сразу несколько. Значения соответствуют `category` из массива. |
| Сортировка | По цене ↑/↓ и по названию; метод `sort()` вызывается у копии `[...selected]`, исходный массив не меняется. |
| Пустое состояние | Сообщение «Ничего не найдено», подсказка и кнопка сброса фильтров. |
| Количество результатов | Над каталогом отображается «Найдено товаров: N из 12». |
| Валидация | `order.html`, `contacts.html`, форма быстрого заказа и корзина; обязательные поля, формат email, телефон с минимум 10 цифрами, согласие, проверка остальных ограничений формы. |
| Сообщения | Ошибка под полем (`aria-describedby`, `aria-invalid`), общая строка результата внутри формы, уведомления на странице; `alert()` не применяется. |
| События | `addEventListener('input' / 'change' / 'click' / 'submit' / 'reset')`; inline-обработчики в HTML не используются. |

### Как работает поиск и фильтрация

Функция `apply()` в `catalog.js` читает поисковый запрос, выбранные категории, границы цены и сортировку. Далее применяет `products.filter()`, создаёт **копию** результата, при необходимости сортирует и рисует карточки через `grid.replaceChildren(...selected.map(createProductCard))`. Поиск запускается через `input` с небольшой задержкой, фильтрация и сортировка также реагируют на `change`. Применённые условия записываются в URL с помощью `URLSearchParams` и `history.replaceState`.

### Как работает валидация

`enhanceForm()` из `validation.js` отменяет стандартную отправку через `event.preventDefault()`, проверяет поля `checkValidity()` и дополнительную длину телефона, показывает сообщение под каждым неверным полем, ставит `aria-invalid="true"` и переводит фокус к первой ошибке. По мере исправления поля ошибка исчезает. Если все поля заполнены корректно, появляется сообщение **«Заявка подготовлена»** и форма очищается. Реальной отправки нет.

## Самостоятельные доработки для повышенной оценки

- **Корзина:** добавление из каталога или страницы товара, изменение количества (1–99), удаление; состояние показывается в `cart.html`.
- **Расчёт через `reduce()`:** стоимость каждой позиции = `price × quantity`, итог — сумма по массиву позиций; отдельный счётчик товаров в меню.
- **Сохранение в `localStorage`:** корзина и избранное переживают перезагрузку и переход между страницами. При недоступности хранилища приложение не должно падать.
- **Избранное:** кнопка с `aria-pressed`, состояние видно при повторном открытии карточки.
- **Промокод:** `ICE10` — демонстрационная скидка **10 %**, пересчитывает итог на странице корзины.
- **Тёмная тема:** кнопка в подвале сайта; переключение через `classList`, выбранная тема сохраняется.
- **Доступность и UX:** счётчик, статусы наличия, отдельная страница корзины, пустые состояния, сообщения в DOM, сохранённые адаптивные изображения `picture/srcset`.
- **Имитация заявки из корзины:** клиентская валидация, сообщение об успешной подготовке, очистка корзины при корректном заполнении. Заявка не отправляется на сервер.

## Сценарии проверки для защиты

1. Откройте **Каталог**: отображаются **12 карточек**, созданных JavaScript.
2. Введите `шлем`: останется один товар. Введите `несуществующий`: увидите пустое состояние и кнопку сброса.
3. Отметьте «Одежда»: должно остаться **3 товара**. Снимите галочку.
4. Выберите «Сначала дешевле» и сравните цены карточек; порядок меняется, исходный массив в `data.js` остаётся прежним.
5. Нажмите «В корзину», откройте **Корзина**, поменяйте количество, удалите/добавьте товар. Проверьте итоговую сумму и счётчик в меню.
6. Введите в корзине промокод `ICE10`: появляется скидка 10 %.
7. Обновите страницу — корзина сохранится. Нажмите «♡ В избранное» и проверьте, что выбор сохраняется. В подвале переключите тему и обновите страницу.
8. На странице **Оформить заявку** нажмите кнопку отправки с пустыми полями: под полями появятся ошибки, фокус перейдёт на первое некорректное поле. Введите неверный email и телефон; исправьте их. Затем заполните обязательные поля и проверьте сообщение об успешной подготовке заявки.
9. На главной нажмите «Быстрый заказ» у популярного товара: откроется модальное окно. Закройте его клавишей Esc или кнопкой «×».
10. Откройте **F12 → Console** на `index.html`, `catalog.html`, `product.html?id=helmet`, `cart.html`, `order.html`, `contacts.html` и убедитесь, что ошибок JavaScript нет.

### Проверка данных командой Node.js (необязательно)

```bash
node tests/smoke.js
```

Проверяются структура и количество товаров, расчёт суммы и счётчика, сохранение, удаление, избранное. Для браузерной работы Node.js не нужен.

## Как сдать

1. Создайте **новый** репозиторий на GitHub с названием `kr4-js-shop` (не заменяйте репозиторий КР №3).
2. Загрузите туда содержимое этой папки. Лучше сделать несколько осмысленных коммитов: перенос КР №3 → генерация каталога → корзина → валидация → README.
3. Для GitHub Pages в настройках репозитория включите **Settings → Pages → Deploy from a branch**, ветка `main`, папка `/ (root)`.
4. Если сайт опубликован, добавьте сюда настоящую ссылку на **КР №4**. Ссылка на КР №3 не является ссылкой на КР №4.
5. В СДО сдайте **ссылку на новый репозиторий**, как указано в методических указаниях.

**Ссылка на репозиторий КР №4:** *вставить после публикации на GitHub*.

## Страница избранного (доработка)

- `favorites.html` — отдельная страница избранных товаров с пустым состоянием.
- Кнопка «Избранное» в навигации всех страниц и счётчик сохранённых товаров.
- В `js/cart.js` функция `toggleFavorite()` сохраняет ID товаров в `localStorage`, `renderFavorites()` отображает их карточки, а `refreshFavoriteButtons()` обновляет состояние кнопок и счётчик.
- На странице избранного можно удалить товар из списка или добавить его в корзину.
- Для проверки: добавить товар в каталоге, открыть «Избранное», обновить страницу, удалить товар и проверить пустое состояние.
